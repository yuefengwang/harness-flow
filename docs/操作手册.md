## 零、环境准备

### 0.1 依赖安装

```bash
pip install pyyaml rich fastapi uvicorn
```

### 0.2 配置凭证

```bash
# 复制凭证模板
cp config/credentials-template.yaml config/credentials.yaml

# 编辑 credentials.yaml，填入 API Key
# 至少需要以下之一：
#   - OPENCODE_API_KEY (用于 OpenCode Agent)
#   - GOOGLE_API_KEY   (用于 Gemini Agent)
```

### 0.3 配置角色（可选）

编辑 `config/config.yaml` 可以为不同阶段分配不同模型：

```yaml
harness:
  stage_roles:
    "01-brainstorming": "analyst"     # 需求分析 — 建议用高能力模型
    "02-planning":     "architect"    # 架构设计 — 建议用高能力模型
    "03-coding":       "developer"    # 编码实现 — 可用低成本模型
    "04-review":       "reviewer"     # 代码审查
    "05-archive":      "archivist"    # 文档归档 — 可用低成本模型
  roles:
    analyst:
      agent: opencode
      model: opencode/deepseek-v4-pro          # 贵模型做设计
      tools: [read_file, ask_user]
    architect:
      agent: opencode
      model: opencode/deepseek-v4-pro          # 贵模型做设计
      tools: [read_file, write_file, ask_user]
    developer:
      agent: opencode
      model: opencode/deepseek-v4-flash-free   # 便宜模型写代码
      tools: [read_file, write_file, run_command]
```

### 1.5 Agent 控制台（核心交互界面）

点击任务详情页的 `[进入对话]` 按钮进入。**这是与 AI Agent 实时交互的核心界面。**

#### 界面布局
```
┌──────────────────────────────────────────────────────┐
│ 任务名: my-task    阶段: 头脑风暴    ○ idle    [启动] │
├──────────────────────────────────────────────────────┤
│ [10:30:15] sw     | 启动 Agent (deepseek-v4-pro)...  │
│ [10:30:18] agent  | 你好！我是需求分析专家。          │
│ [10:30:19] agent  | 我理解你需要开发一个电商应用。    │
│                   | 在开始设计之前，我需要确认...      │
│ [10:30:20] system | ❓ opencode 提出 3 个问题         │
│ ...                                                  │
├──────────────────────────────────────────────────────┤
│ 💬 输入消息或 /命令                                   │
│ [________________________________________]  [发送]    │
└──────────────────────────────────────────────────────┘
```

#### 操作步骤

**Step 1: 启动引擎**

点击 `[启动引擎]` 按钮。系统会：
1. 创建 WebEngineSession（一个 SSE 连接 + Agent 实例）
2. 自动注入上下文（角色提示 + 前序产出 + 当前模板 + 需求描述 + 合规规则）
3. Agent 开始工作，日志实时流式推送到控制台

**Step 2: 与 Agent 交互**

| 输入方式 | 格式 | 示例 |
|---------|------|------|
| 自由文本 | 直接输入 | `我希望支持用户注册和登录功能` |
| 选项选择 | 输入标签字母 | `A` / `B` / `C` |
| 斜杠命令 | `/command` | `/advance` / `/status` / `/q` |

**Step 3: 回答 Agent 的结构化提问**

当 Agent 使用 `ask_user` 工具发起提问时，控制台底部会切换为问答模式：

```
❓ Agent 正在等待回答

❓ [1/3] 你希望支持哪些用户角色？
  [A] 仅普通用户
  [B] 普通用户 + 管理员
  [C] 支持自定义角色

👉 请输入 A/B/C 选择: _
```

选择一个选项后自动进入下一个问题。全部回答完成后答案自动路由回 Agent。

**Step 4: 推进阶段**

当 Agent 告知当前阶段工作完成后，输入 `/advance` 推进到下一阶段。系统会自动：
1. 保存当前阶段产出到 `.md` 文件
2. 执行后置 Hook 校验
3. 更新阶段状态
4. 启动下一阶段的 Agent

#### 斜杠命令速查

| 命令 | 功能 |
|------|------|
| `/advance` | 校验当前阶段并推进到下一阶段 |
| `/status` | 查看当前任务状态 |
| `/q` | 退出控制台 |

#### SSE 事件说明

控制台通过 SSE (Server-Sent Events) 接收以下事件类型：

| 事件类型 | 触发时机 | 显示效果 |
|---------|---------|---------|
| `log` | Agent 输出任何内容 | 日志行追加到控制台 |
| `question` | Agent 发起结构化提问 | 底部切换为问答模式 |
| `settlement` | 任务全部阶段完成 | 显示结算选项 |
| `status` | Agent 状态变化 | 更新顶部状态指示灯 |
| `state` | 阶段变更 | 更新阶段名称 |

**连接断开恢复**：SSE 连接断开后自动每 5 秒重试，控制台显示 `⚠️ SSE 连接断开，5 秒后重连...`。

### 1.6 一键部署

**前提条件**：任务状态为 `Finished`（完成所有 5 个阶段）。

**操作**：在任务看板中点击 Finished 任务的 `[部署]` 按钮。

**流程**：
1. 系统读取任务的 `target_dir`（代码生成目录）
2. 后台启动 Agent（使用 developer 角色，有 run_command 权限）
3. Agent 进入项目目录，自动检测项目类型：
   - `Dockerfile` / `docker-compose.yml` → Docker 部署
   - `package.json` → `npm install && npm start`
   - `pom.xml` / `build.gradle` → Maven/Gradle 启动
   - `requirements.txt` → `pip install && python app.py`
   - `go.mod` → `go run .`
4. 启动服务后，自动创建 Cloudflare Tunnel 公网访问
5. 部署完成后，任务详情页出现「打开应用」入口按钮

**状态追踪**：

| 状态 | 看板显示 |
|------|---------|
| `idle` | 绿色 `[部署]` 按钮 |
| `deploying` | 灰色 `部署中...` |
| `deployed` | 绿色 `已部署` + 访问链接 |
| `deploy_failed` | 红色 `部署失败` + `[重试]` 按钮 |

### 2.3 状态图标说明

Header 中的状态指示灯：

| 图标 | 状态 | 含义 |
|------|------|------|
| ⏳ (黄) | connecting | 正在连接 AI Agent |
| ● (绿) | active | Agent 正在运行中 |
| ◉ (黄) | waiting | Agent 正在等待用户回复 |
| ○ (灰) | idle | Agent 空闲 |
| ✘ (红) | error | 连接异常 |

### 2.4 输入模式

TUI 能根据 Agent 的回复内容**自动识别**当前应该处于哪种交互模式：

#### 自由输入模式（none）
```
💬 输入消息或 /命令 (如 /advance, /q)
👉: _
```
Agent 没有提出具体问题时使用。可以输入任意文本或斜杠命令。

#### Yes/No 确认模式
```
📢 Agent 请求确认。请输入 yes 或 no
👉: _
```
自动触发条件：Agent 说"是否同意?""可以进入下一阶段吗?"等确认语句。

#### 选项选择模式
```
  [A] 仅普通用户
  [B] 普通用户 + 管理员
  [C] 支持自定义角色
👉 请输入 A/B/C 选择: _
```
自动触发条件：Agent 输出中包含 `- **选项 A**:` 或 `1. xxx` 等格式化选项。

#### 结构化提问模式
```
❓ [1/3] 你希望支持哪些用户角色？
  [A] 仅普通用户
  [B] 普通用户 + 管理员
  [C] 支持自定义角色
👉 请输入 A/B/C 选择: _
```
由 Agent 的 `ask_user` 工具触发，支持多轮问答。回答完当前问题自动进入下一个。

### 2.5 斜杠命令

| 命令 | 功能 | 说明 |
|------|------|------|
| `/advance` | 推进阶段 | 校验当前阶段产出 → 进入下一阶段 → 自动启动新 Agent |
| `/status` | 查看状态 | 显示当前任务阶段和状态 |
| `/context` | 上下文预览 | 显示注入给 Agent 的上下文前 300 字符 |
| `/restart` | 重启 Agent | 关闭当前 Agent 并重新启动（清空会话） |
| `/answer` | 编程式回复 | `/answer 我选择方案B` |
| `/q` | 退出 | 保存并退出监控面板 |

### 2.6 键盘快捷键

| 快捷键 | 功能 |
|--------|------|
| ↑ | 向上滚动日志历史（1 行） |

| PageDown | 向下翻页 |

## 三、CLI 命令行

### 3.1 命令速查表

| 命令 | 说明 | 示例 |
|------|------|------|
| `./sw init` | 创建新任务（零参数进入交互模式） | `./sw init` |
| `./sw init --name=my-app --type=feature --context="做一个电商应用"` | 非交互式创建 | `./sw init --name=my-app --context="..."` |
| `./sw monitor --name=my-task` | 启动 TUI 监控面板 | `./sw monitor --name=my-app` |
| `./sw dashboard` | 启动 Web Dashboard | `./sw dashboard --port 3000` |
| `./sw status --name=my-task` | 查看任务状态 | `./sw status --name=my-app` |
| `./sw advance --name=my-task` | 推进阶段 | `./sw advance --name=my-app` |
| `./sw list` | 列出活跃任务 | `./sw list` |
| `./sw list --trash` | 查看回收站 | `./sw list --trash` |
| `./sw remove --name=my-task` | 软删除任务 | `./sw remove --name=my-app` |
| `./sw restore --name=my-task` | 恢复任务 | `./sw restore --name=my-app` |
| `./sw answer --name=my-task --text="方案A"` | 以编程方式回复 Agent | `./sw answer --name=my-app --text="A"` |
| `./sw resume --name=my-task` | 恢复并查看上下文 | `./sw resume --name=my-app` |

全局标志：`--yes/-y`（自动确认所有提示）、`--non-interactive`（非交互模式）。

### 3.2 完整使用流程示例

```bash
# 1. 创建任务（交互式）
./sw init

# → 浏览器打开 http://127.0.0.1:8080

```

## 四、常见问题排查

### 4.1 Dashboard 无法访问

```bash
# 检查是否被防火墙拦截
curl http://127.0.0.1:8080

# 检查端口是否被占用
lsof -i :8080

# 更换端口启动
./sw dashboard --port 3000
```

### 4.2 Agent 无法启动

```bash
# 检查凭证文件
cat config/credentials.yaml

# 检查 opencode CLI 是否安装
which opencode
opencode --version

# 尝试切换 Agent 类型
# 编辑 config/config.yaml，将 agent: opencode 改为 agent: gemini
```

### 4.3 TUI 显示异常

```bash
# 检查 Rich 库是否安装
python3 -c "import rich; print(rich.__version__)"

# 重新安装
pip install --upgrade rich
```

### 4.4 部署失败

```bash
# 查看部署日志
cat workspace/tasks/<任务名>/.deploy_log

# 常见原因：
# 1. 目标目录不存在 → 检查 repo/<任务名>/ 是否存在
# 2. 项目类型未识别 → 确保项目目录中有 package.json/pom.xml/requirements.txt 等
# 3. Cloudflare Tunnel 问题 → 检查 cloudflared 是否安装: which cloudflared
```

### 4.5 SSE 连接断开

SSE 连接断开后会自动重连。如持续失败：
1. 检查 Dashboard 是否仍在运行
2. 刷新浏览器页面
3. 重启 Dashboard：`./sw dashboard`

### 4.6 任务无法推进

```bash
# 查看未完成的校验项
./sw status --name=<任务名>

# 检查阶段模板中的 [ ] 是否全部勾选
cat workspace/tasks/<任务名>/03-coding.md | grep "\[ \]"

# 手动勾选 Gate 章节中的待办项后重试
```

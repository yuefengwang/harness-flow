# 03-Coding Hooks

## hook-03-01: 编译保证

- **触发**: post (每个子任务完成时)
- **规则**: 代码必须成功编译，任务才算完成。构建失败时必须诊断并修复
- **验证**: `mvn compile` 或等效命令退出码为 0

## hook-03-02: TDD 循环

- **触发**: during (每个编码单元)
- **规则**: 严格遵循 RED → GREEN → REFACTOR
- **验证**:
  - RED: 已编写失败测试
  - GREEN: 最少代码使测试通过
  - REFACTOR: 优化后测试仍为绿色

## hook-03-03: 复杂逻辑设计模式

- **触发**: during (遇到复杂分支/多实现/状态管理)
- **规则**: 使用显式设计模式（策略、工厂、观察者等），禁止深层嵌套 if/else
- **验证**: 无超过 3 层的嵌套条件，或已使用模式替代

## hook-03-04: 强制注释

- **触发**: during (编码时)
- **规则**: 所有复杂逻辑、非直观算法、关键业务决策必须配备注释；公共 API 必须有 Javadoc
- **验证**: 代码评审时确认关键路径均有注释

## hook-03-05: 原子提交

- **触发**: post (编码单元完成后)
- **规则**: 遵循 `feat:` / `fix:` / `refactor:` 等 Conventional Commits 规范
- **验证**: `git log -1` 显示规范的 commit message
